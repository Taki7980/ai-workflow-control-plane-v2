# V2.2 research notes — 2026-09-07

This document records the research used to extend AI Workflow V2.1 into V2.2. The implementation intentionally keeps the core dependency-free and deterministic. Research ideas that require learned routing, calibrated uncertainty, or mandatory embedding infrastructure are documented but not presented as guarantees.

## 1. Budget-constrained context assembly

**PACMS: Submodular Context Selection as a Pluggable Engine for LLM Agents** (2026)

https://arxiv.org/abs/2606.20047

The useful abstraction is prompt assembly as a budgeted coverage problem rather than a pure ranking problem. Let candidate contexts be `C`, selected set `S`, budget `B`, and pairwise coverage weights `w_ij`. A facility-location objective is:

```text
F(S) = Σ_i max_{j∈S} w_ij
subject to Σ_{j∈S} cost(j) ≤ B
```

V2.2 implements a deterministic dependency-free approximation:

```text
r_i = 0.65 * normalized_source_score_i + 0.35 * Jaccard(query_tokens, item_tokens_i)
w_ij = r_i * Jaccard(tokens_i, tokens_j)
F(S) = Σ_i max_{j∈S} w_ij
```

Mandatory structural evidence is inserted first. Normal budgets use lazy greedy marginal-gain-per-character selection; very tight budgets use relevance-first selection. This preserves the research intuition that coverage helps when there is enough budget to diversify, while very tight budgets can favor direct relevance.

The Jaccard term is explicitly a lexical approximation. It is not described as embedding cosine similarity.

## 2. Retrieval-conditioned orchestration

**RGAO: Retrieval-Conditioned Topology Selection with Provable Budget Conservation for Multi-Agent Code Generation** (2026)

https://arxiv.org/abs/2605.05657

RGAO motivates conditioning an agent topology on codebase-derived structural complexity and conserving a parent resource budget when allocating child agents/tools. V2.2 adopts the architectural principle, not its learned router.

The local deterministic complexity vector is:

```text
[
  lane_weight,
  risk_weight,
  changed_file_count,
  workspace_root_count,
  structural_intent,
  evidence_gap
]
```

This controls bounded `agent_slots`, graph depth, review passes, verification passes, and CRG call count. Every selected value is capped by the configured parent orchestration budget.

**Codebook Agent: Learning Topology Codebooks for Multi-Agent Systems** (2026-09-02)

https://arxiv.org/abs/2609.02264

Recent work continues to show that multi-agent topology affects both quality and token cost. V2.2 does not introduce a learned topology codebook because the project does not yet have reliable outcome labels needed to make that safe and measurable.

## 3. Repository retrieval and selective evidence

**Agent Retrieval Bench: Evaluating Repository Context Retrieval for Coding Agents** (2026-07-27)

https://arxiv.org/abs/2607.24882

The benchmark covers code-to-test, comment-to-context, trace-to-code, edit-ripple and no-gold/counterfactual retrieval. Its central design implication is that no single retriever dominates across repository tasks. It also highlights a calibration gap between synthetic counterfactual no-gold controls and natural no-gold queries.

V2.2 therefore:

- keeps exact, semantic, structural and mixed retrieval routes;
- adds no-gold regression cases;
- exposes `sufficient`, `requires_exploration`, and `abstain` states;
- does not claim the sufficiency heuristic is statistically calibrated.

**CORE-Bench: A Comprehensive Benchmark for Repository-Level Code Retrieval** (2026)

https://arxiv.org/abs/2606.11864

CORE-Bench reinforces that repository-level retrieval is broader than isolated snippet matching. This supports keeping graph/workspace retrieval separate from lexical retrieval and measuring repository-context behavior directly.

## 4. Context precision, density and experience

**ContextBench** (2026)

https://arxiv.org/abs/2602.05892

ContextBench reports that coding agents often favor context recall over precision and distinguishes explored context from actually utilized context. V2.2 adds relevant-item density and matched-pattern yield per 1K estimated context tokens to avoid optimizing recall alone.

**SWE Context Bench** (2026)

https://arxiv.org/abs/2602.08316

The study finds useful summarized experience can improve software-engineering performance, while incorrect/unfiltered experience can hurt. This reinforces V2.1/V2.2's durable-memory rules: freshness/provenance remain mandatory, and memory competes for context budget instead of bypassing retrieval controls.

## 5. Workspace-state consistency

**StagedWorkspace** (2026-08-18)

https://arxiv.org/abs/2608.18050

StagedWorkspace motivates binding structured views and edits to concrete workspace/native-file versions. V2.2 adds a stable workspace fingerprint derived from resolved root, Git HEAD when available, index-state digest, and changed-file content hashes/states. Downstream agents can detect that a context packet was built against a different workspace state.

## 7. Superpowers integration

Superpowers releases, checked 2026-09-07:

https://github.com/obra/superpowers/releases

The latest observed release is v6.3.0 (2026-08-12), including Hermes support and task-scaled brainstorming behavior. V2.2 avoids coupling to internal implementation details and emits skill-level contracts:

- Answer: direct, no Superpowers workflow.
- Small: `test-driven-development` -> `verification-before-completion` when Superpowers is available.
- Full: `writing-plans` -> `subagent-driven-development` -> `requesting-code-review` -> `verification-before-completion`.
- If Superpowers is unavailable, retain the native fallback.

The emitted skill sequence is a control-plane contract; Superpowers remains responsible for its internal methodology and subagent state.

## 8. Uncertainty and adaptive routing — future work

Recent conformal/selective RAG and contextual-bandit routing research is useful, but production guarantees require representative calibration/outcome data. V2.2 therefore keeps routing confidence and retrieval sufficiency heuristic and transparent.

Future evaluation can investigate:

- conformal abstention thresholds trained on representative natural no-gold tasks;
- bandit selection among retriever/tool policies using verified task outcomes;
- learned agent topology after enough labeled end-to-end runs exist;
- dense embeddings inside the facility-location selector when an optional semantic provider exposes stable vector similarities.

These are not current claims or hidden behavior.
