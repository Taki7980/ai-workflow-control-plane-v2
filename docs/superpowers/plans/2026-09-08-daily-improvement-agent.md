# Daily Improvement Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the dormant/older daily improvement Agentic Workflow with the approved evidence-gated maintainer and add a separate weekly onboarding workflow.

**Architecture:** Keep `daily-research.yml` as the sole research scout. The daily Agentic Workflow consumes the scout branch, establishes a fresh `main` benchmark baseline, performs the promotion gate plus maintenance pass, and emits at most one safe PR or one security-review issue. Weekly onboarding is a separate Agentic Workflow with its own branch prefix and no research implementation scope.

**Tech Stack:** GitHub Agentic Workflows (`gh-aw`), OpenAI Codex engine, GitHub safe outputs, Python 3.10+ project verification commands.

**Spec:** `docs/superpowers/specs/2026-09-08-daily-improvement-agent-design.md`

## Global Constraints

- Do not duplicate the existing research scout.
- Do not weaken deterministic escalation for auth, authorization, security, payments/billing, schema/migrations, concurrency, deployment, credentials, destructive data changes, or public contracts.
- Do not add runtime dependencies.
- Never self-merge.
- At most one open `automation/daily-improve-*` PR at a time.
- Daily implementation diff target: under roughly 400 changed lines excluding generated research/docs output.
- Hard benchmark non-regression metrics: `lane_accuracy`, `intent_accuracy`, `evidence_state_accuracy`, `abstention_accuracy`.
- `.lock.yml` files are compiler output and must be generated by `gh aw compile`, never hand-authored.

### Task 1: Replace daily improvement policy

**Files:**
- Modify: `.github/workflows/daily-improvement.md`

**Interfaces:**
- Consumes: `automation/daily-research:docs/research/daily/latest.md`, current `main`, GitHub PR/issue/Actions history.
- Produces: zero or one safe daily improvement PR, or a security-review issue when a sensitive fix is uncertain.

- [ ] **Step 1: Encode the schedule and least-privilege read tools**

Use a fixed daily schedule after the scout:

```yaml
on:
  schedule:
    - cron: "0 7 * * *"
  workflow_dispatch:
```

Keep the agent read-only and provide write operations only through safe outputs.

- [ ] **Step 2: Restrict code-writing safe outputs**

Configure `create-pull-request` and `push-to-pull-request-branch` with the same exclusive allowlist:

```yaml
allowed-files:
  - ai_workflow/**
  - tests/**
  - benchmarks/**
  - docs/research/**
  - README.md
  - ARCHITECTURE.md
```

Set `protected-files.policy: blocked` while excluding only `README.md` and `ARCHITECTURE.md` from protected-file blocking because those two files are explicitly within the approved documentation boundary. Do not allow `.github/**`, `AGENTS.md`, `LICENSE`, or `pyproject.toml`.

- [ ] **Step 3: Encode daily algorithm in the Markdown body**

Require the agent to:

```text
sync main
fetch automation/daily-research
read AGENTS.md + ARCHITECTURE.md + README.md
read latest.md via git show origin/automation/daily-research:docs/research/daily/latest.md
list open PRs/issues and prior rejected work
run fresh main benchmark baseline
apply seven-part promotion gate
implement at most one candidate
always perform maintenance pass
run mandatory verification
compare four blocking metrics
emit safe PR only when all gates pass
otherwise emit no code PR
```

- [ ] **Step 4: Encode PR/update behavior and audit policy**

Require branch names `automation/daily-improve-YYYY-MM-DD`. If an open matching PR exists, use `push-to-pull-request-branch` and `update-pull-request` instead of opening another. Require `ops-log.md` only when code is already being proposed; rely on Actions run logs/summary for no-change runs.

- [ ] **Step 5: Validate source frontmatter with the official compiler**

Run:

```bash
gh aw compile daily-improvement
```

Expected: successful compilation and generated `.github/workflows/daily-improvement.lock.yml`.

- [ ] **Step 6: Commit source plus compiler output**

```bash
git add .github/workflows/daily-improvement.md .github/workflows/daily-improvement.lock.yml
git commit -m "ci: harden daily improvement agent"
```

### Task 2: Add weekly onboarding workflow

**Files:**
- Create: `.github/workflows/weekly-onboarding.md`
- Create (compiler output): `.github/workflows/weekly-onboarding.lock.yml`

**Interfaces:**
- Consumes: documented quick start and current repository source.
- Produces: zero or one `automation/weekly-onboarding-*` PR containing setup/DX fixes only.

- [ ] **Step 1: Create the weekly Agentic Workflow source**

Use `engine: codex`, a weekly Monday schedule around 12:30 IST, read-only agent permissions, edit/bash tools, and a single safe PR output restricted to setup/DX source/tests/docs. Explicitly forbid research-driven retrieval/routing optimization in this workflow.

- [ ] **Step 2: Encode clean-environment onboarding smoke commands**

Require:

```bash
python -m pip install -e .
ai-workflow bootstrap --project-name SmokeProject
ai-workflow doctor --strict
ai-workflow index --incremental
ai-workflow brief "refactor payment retry handling" --format prompt
```

Use a temporary directory for the bootstrap target when necessary so the repository checkout itself is not polluted by smoke-test state.

- [ ] **Step 3: Compile the workflow**

Run:

```bash
gh aw compile weekly-onboarding
```

Expected: successful compilation and generated `.github/workflows/weekly-onboarding.lock.yml`.

- [ ] **Step 4: Commit source plus compiler output**

```bash
git add .github/workflows/weekly-onboarding.md .github/workflows/weekly-onboarding.lock.yml
git commit -m "ci: add weekly onboarding agent"
```
